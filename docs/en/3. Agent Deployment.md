# Docker container deployment

This section explains how a **runtime-server** instance starts **containerized low-code Agents** under different deployment modes: steps, configuration, and caveats for operators and developers.

## Process-based runtime-server → containerized low-code Agent

When runtime-server runs as a **process**, you can start low-code Agents in containers in two ways.

### Option A: specify mode in the HTTP request

Send an HTTP **POST** with **`mode=docker`** to start a containerized low-code Agent on demand — useful for ad-hoc or temporary container runs.

Example (replace placeholders for your environment):

```text
curl -X POST "http://<RUNTIME_HOST>:<RUNTIME_PORT>/api/v1/agents/deploy?name=<AGENT_NAME>&mode=docker" -F "file=@<PATH_TO_IR_JSON>"
```

**Parameters:**

- `<RUNTIME_HOST>`: Hostname or IP where runtime-server runs (reachable from the client);
- `<RUNTIME_PORT>`: Listen port (same as `PORT` in `server/.env`);
- `<AGENT_NAME>`: Your low-code Agent name (e.g. `business-lowcode-agent`);
- `<PATH_TO_IR_JSON>`: Path to the low-code Agent IR JSON file (absolute or relative), readable from the shell where you run `curl`.

### Option B: fix mode in configuration

In `server/.env`, set:

```text
DEPLOY_TYPE=docker
```

After restart, runtime-server **always** starts low-code Agents in containers, regardless of request parameters — for environments that must be uniformly containerized.

**Note:** Restart runtime-server after changing this file.

## Docker-based runtime-server → containerized low-code Agent

When **runtime-server itself** runs inside Docker, starting containerized low-code Agents falls into either manual container runs or a one-click deploy tool.

### Scenario 1: manual `docker run` for runtime-server

Ensure `.env` sets **`DEPLOY_TYPE=docker`**. Mount the env file and the Docker socket so the container can talk to the host Docker daemon.

Example:

```text
docker run -d --name <RUNTIME_CONTAINER_NAME> \
  -v <HOST_PATH_TO_.env>:/app/site-packages/openjiuwen_runtime/server/.env \
  -v /var/run/docker.sock:/var/run/docker.sock \
  <RUNTIME_SERVER_IMAGE>
```

**Notes:**

- `<RUNTIME_CONTAINER_NAME>`: e.g. `studio-runtime-server-prod`;
- `<HOST_PATH_TO_.env>`: absolute path to your host `.env`; must include `DEPLOY_TYPE=docker`;
- Mounting **`/var/run/docker.sock`** lets runtime-server on the host (inside the container) start sibling low-code Agent containers;
- `<RUNTIME_SERVER_IMAGE>`: full image name and tag for runtime-server.

### Scenario 2: official one-click deploy tool

If you use the provided one-click tool, it sets `DEPLOY_TYPE=docker` and required mounts automatically. After startup, low-code Agents start in container mode without extra manual steps.

## Caveats

- For any mode that runs low-code Agents in Docker, the **host Docker daemon must be running** and runtime-server must be allowed to use it;
- When mounting `.env`, verify the path is correct or configuration will not load; **`DEPLOY_TYPE=docker`** is required for containerized low-code Agents in these flows;
- On failures, check **`DEPLOY_TYPE`**, runtime-server container logs, and Docker connectivity;
- When runtime-server is containerized, low-code Agents should run in containers as designed; mismatched modes can leave Agents unable to serve traffic.
