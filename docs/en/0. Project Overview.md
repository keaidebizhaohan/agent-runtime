# openJiuwen Agent Runtime — Project Overview

openJiuwen Agent Runtime (Runtime) is the agent operations platform in the openJiuwen stack. It publishes Agents finished in development into callable online services.  
It provides unified deployment, querying, decommissioning, and state management so teams can move smoothly from “building agents” to “running agents reliably.”

## Positioning

Runtime focuses on:

- Deploying different types of Agents in a uniform way and exposing them as services;
- Isolating runtime instances across tenants (users and spaces);
- Supporting multiple deployment modes (process, Docker, Kubernetes);
- Managing the lifecycle of running Agents (deploy, inspect, delete, health checks).

## Core capabilities

### 1) Unified deployment management

Runtime exposes standard REST APIs. You deploy Agents using configuration files and metadata, and can:

- Deploy new Agents;
- List deployments and fetch details;
- Remove deployed instances;
- Confirm instance health via health checks.

### 2) Multiple deployment strategies

Runtime uses a strategy-based deployment model with three modes:

- `subprocess`: run each Agent in an isolated subprocess (default);
- `docker`: run Agents in containers;
- `k8s`: run Agents on a Kubernetes cluster.

### 3) Multi-tenant isolation

Runtime can inject tenant context into the request path (e.g. `user_id`, `space_id`) to isolate resources and operations per tenant.

### 4) Extensible architecture

Runtime is modular: deployment strategies, Agent types, and foundational capabilities can be extended independently for different business scenarios.

## Architecture

The Runtime repository is organized into:

- `server/`: FastAPI management service — deployment and management APIs;
- `management/`: deployment core — strategy selection and lifecycle orchestration;
- `foundation/`: shared building blocks (configuration, database, ports, virtual environments, etc.);
- `service/`: Agent service base classes — common interfaces such as query and health;
- `applications/`: concrete Agent implementations (e.g. low-code Agent, workflow Agent).

## Typical deployment flow

1. The client calls Runtime’s deploy API with Agent configuration;
2. Runtime picks a deployment strategy and creates a deployment record;
3. The strategy executor starts the instance (process / container / K8s);
4. The Agent service starts and exposes standard endpoints (e.g. `/query`, `/health`);
5. Callers use Runtime or the Agent’s own address for traffic and operations.

## When to use Runtime

- One-click publish from openJiuwen Studio to a runtime environment;
- Shared Agent platform for multiple teams and tenants inside an enterprise;
- Standardized delivery of Agents from test to production;
- Mixed infrastructure where deployment mode may change by policy.
