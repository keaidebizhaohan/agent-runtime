介绍 Runtime Management 的安全 SDK（`openjiuwen_runtime.management.security`）：以通用接口提供**加解密**、**加签验签**、**证书/密钥管理**三块能力，供节点管理、配置下发等场景按需引入。实现可插拔（默认 Ed25519 + X25519/AES-256-GCM），调用方只依赖接口。

# 概述

| 能力 | 默认实现 | 通用接口 |
| --- | --- | --- |
| 加解密 | AES-256-GCM（对称）+ X25519 信封（面向公钥的混合加密） | `ICryptoProvider` |
| 加签 | Ed25519 | `ISigner` |
| 验签 | Ed25519 | `IVerifier` |
| 证书/密钥管理 | 基于 foundation `DBHandler` 落库 | `ICertificateManager` |

设计要点：

- **非对称只解决密钥分发，数据仍对称加密**：信封加密里，大数据用一次性 DEK（AES-256-GCM）加密保证效率，DEK 再用对端公钥包裹随密文下发——两端无需预共享密钥即可安全通信。
- **私钥永不外发**：本端私钥落库受保护，只导出公钥用于握手交换。
- **不绑定传输**：密钥交换给出传输无关的 `KeyExchange`（begin/complete），调用方接到自己的通道（WebSocket / HTTP 等）。

引入：

```python
from openjiuwen_runtime.management.security import (
    EnvelopeCryptoProvider, Ed25519Signer, Ed25519Verifier,
    CertificateManager, server_key_exchange, client_key_exchange, KeyPurpose,
)
```

# 加解密（信封）

`ICryptoProvider` 既提供对称 AEAD，也提供面向公钥的信封加密：

```python
crypto = EnvelopeCryptoProvider()

# 信封：用对端公钥加密，对端用自己的私钥解密
sealed = crypto.seal(recipient_public, b"kubeconfig-SECRET")   # -> SealedMessage(epk, wrapped_key, ciphertext)
plaintext = crypto.open(recipient_private, sealed)             # -> b"kubeconfig-SECRET"

# 对称 AEAD（已有 32 字节密钥时直接用）
key = crypto.generate_data_key()
ct = crypto.aead_encrypt(key, b"data", associated_data=b"aad")
pt = crypto.aead_decrypt(key, ct, associated_data=b"aad")
```

`SealedMessage` 字段：`epk`（临时 X25519 公钥）、`wrapped_key`（被包裹的 DEK）、`ciphertext`（AES-256-GCM 密文）、`dek_algorithm`（`X25519-HKDF-SHA256+AES-256-GCM`）。每次 `seal` 都用全新随机 DEK 与临时公钥。

# 加签验签

```python
signer = Ed25519Signer(private_raw, key_version="v1")   # 持本端私钥
signature = signer.sign(b"config-bytes")

verifier = Ed25519Verifier(peer_public_raw)             # 持对端公钥
ok = verifier.verify(b"config-bytes", signature)        # 校验失败统一返回 False（fail-closed）
```

也可由密钥对/公钥构造：`make_signer(keypair)`、`make_verifier(public_raw)`。

# 证书/密钥管理

`CertificateManager` 负责**密钥与证书的录入、保存、读取、删除**，基于 foundation `DBHandler` 落库（新增两张独立表，不影响既有表）。

**`security_local_key`** —— 本端密钥对（自己持有，含私钥），每种用途一行，主键即用途：

| 列 | 类型(长度) | 主键 | 可空 | 默认 | 说明 |
| --- | --- | :---: | :---: | --- | --- |
| `purpose` | string(32) | ✅ | 否 | — | 用途：`sign` / `encrypt` |
| `algorithm` | string(32) | | 否 | — | `Ed25519` / `X25519` |
| `private_key` | string(512) | | 否 | — | 私钥（base64，永不外发） |
| `public_key` | string(256) | | 否 | — | 公钥（base64） |
| `fingerprint` | string(128) | | 否 | — | 公钥 SHA-256 指纹 |
| `key_version` | string(32) | | 否 | `v1` | 版本（轮换用） |
| `created_at` / `updated_at` | datetime | | 否 | — | 时间戳 |

**`security_peer_key`** —— 对端公钥（握手录入，只存公钥），按 `(peer_id, purpose)` 唯一，主键用合成串 `record_id = "<peer_id>::<purpose>"`：

| 列 | 类型(长度) | 主键 | 可空 | 默认 | 说明 |
| --- | --- | :---: | :---: | --- | --- |
| `record_id` | string(160) | ✅ | 否 | — | `"<peer_id>::<purpose>"` |
| `peer_id` | string(128) | | 否 | — | 对端标识 |
| `purpose` | string(32) | | 否 | — | 该公钥用途 `sign` / `encrypt` |
| `algorithm` | string(32) | | 否 | — | `Ed25519` / `X25519` |
| `public_key` | string(256) | | 否 | — | 对端公钥（base64，**无私钥**） |
| `fingerprint` | string(128) | | 否 | — | 公钥指纹（确认配对/轮换比对） |
| `key_version` | string(32) | | 否 | `v1` | 版本 |
| `status` | string(32) | | 否 | `bound` | 状态（`bound` 已配对等） |
| `created_at` / `updated_at` | datetime | | 否 | — | 时间戳 |
| 索引 | — | | | | `peer_id`、`purpose` 各一个非唯一索引 |

初始化与本端密钥：

```python
cm = CertificateManager(db_handler)
await cm.ensure_ready()                                  # 幂等建表

kp = await cm.get_or_create_keypair(KeyPurpose.SIGN)     # 不存在则生成并落库（Ed25519）
pub = await cm.export_public(KeyPurpose.SIGN)            # 导出本端公钥（用于握手）
```

对端公钥的录入 / 读取 / 删除：

```python
fp = await cm.save_peer_key("gateway-1", KeyPurpose.ENCRYPT, peer_public)  # 录入+保存，返回指纹（确认配对）
peer = await cm.load_peer_key("gateway-1", KeyPurpose.ENCRYPT)             # 读取
await cm.delete_peer_key("gateway-1", KeyPurpose.ENCRYPT)                  # 删某用途
await cm.delete_peer_key("gateway-1")                                      # 解绑：删该对端全部
peers = await cm.list_peer_keys(purpose=KeyPurpose.ENCRYPT.value)         # 列举
```

## 服务端与客户端分别怎么做

证书管理在两端是**镜像**的：本端持自己的密钥对，并保存对端公钥。约定用途：

| 角色 | 本端密钥对 | 保存的对端公钥 | 含义 |
| --- | --- | --- | --- |
| 服务端（如 Manager） | `sign`（Ed25519） | 各客户端的 `encrypt` 公钥 | 服务端签发配置、用客户端公钥加密下发 |
| 客户端（如 Gateway） | `encrypt`（X25519） | 服务端的 `sign` 公钥 | 客户端解密下发、验签 |

## 数据库样例：Manager ↔ Gateway 加解密 + 加签验签

设 Manager（`manager-1`）向 Gateway（`gateway-1`）下发加密 + 加签的配置。握手交换公钥后，两端各自的两张表如下（密钥/指纹为真实生成值，截断显示）。注意**交叉引用**：Gateway 的加密公钥指纹 `b20b291d…` 同时出现在 Gateway 的 local 表与 Manager 的 peer 表；Manager 的签名公钥指纹 `27f0d4b4…` 同时出现在 Manager 的 local 表与 Gateway 的 peer 表。

**Manager 侧** —— 持自己的签名私钥，存 Gateway 的加密公钥：

`security_local_key`

| purpose | algorithm | private_key | public_key | fingerprint | key_version |
| --- | --- | --- | --- | --- | --- |
| `sign` | Ed25519 | `hchf3hFLfIgll5x…`（私钥） | `V4QaWeKM59YZ1WF…` | `27f0d4b4921fbee9…` | v1 |

`security_peer_key`

| record_id | peer_id | purpose | algorithm | public_key | fingerprint | status |
| --- | --- | --- | --- | --- | --- | --- |
| `gateway-1::encrypt` | `gateway-1` | `encrypt` | X25519 | `ziX2VbNUTIbYjK9…` | `b20b291d00666285…` | bound |

**Gateway 侧** —— 持自己的加密私钥，存 Manager 的签名公钥：

`security_local_key`

| purpose | algorithm | private_key | public_key | fingerprint | key_version |
| --- | --- | --- | --- | --- | --- |
| `encrypt` | X25519 | `uHYcTGBCEvJkcck…`（私钥） | `ziX2VbNUTIbYjK9…` | `b20b291d00666285…` | v1 |

`security_peer_key`

| record_id | peer_id | purpose | algorithm | public_key | fingerprint | status |
| --- | --- | --- | --- | --- | --- | --- |
| `manager-1::sign` | `manager-1` | `sign` | Ed25519 | `V4QaWeKM59YZ1WF…` | `27f0d4b4921fbee9…` | bound |

下发时：Manager 用 peer 表里 Gateway 的 `encrypt` 公钥 `seal`（加密）+ 用 local 表里自己的 `sign` 私钥签名；Gateway 用 peer 表里 Manager 的 `sign` 公钥验签 + 用 local 表里自己的 `encrypt` 私钥 `open`（解密）。解绑时删除对应 peer 行即可。

> 说明：本例中 Manager 不需要 `encrypt` 密钥对、Gateway 不需要 `sign` 密钥对（各自只用到自己角色那一种）；若是双向加密/双向签名场景，再各自补另一种用途的本端密钥对即可。

# 握手密钥交换（传输无关）

`KeyExchange` 把"导出本端公钥 / 录入对端公钥"封装成 begin/complete，**不关心怎么传输**；`server_key_exchange` / `client_key_exchange` 给出两端标准角色：

```python
# 服务端
server = server_key_exchange(cm)            # 本端 sign / 录入对端 encrypt
my_sign_pub = await server.begin()          # 放进自己的握手帧发出去（传输由调用方负责）
await server.complete("gateway-1", gateway_enc_pub)   # 收到客户端公钥 → 保存+确认配对

# 客户端
client = client_key_exchange(cm)            # 本端 encrypt / 录入对端 sign
my_enc_pub = await client.begin()
await client.complete("manager-1", manager_sign_pub)
```

> 真实的握手报文时序（走什么协议、何时发）由调用方实现；SDK 只提供与传输无关的密钥这一半。

# 端到端示例

握手换出密钥后，服务端加密+加签、客户端验签+解密：

```python
# 握手后：服务端已保存客户端的 encrypt 公钥；客户端已保存服务端的 sign 公钥
gw_enc_pub = (await server_cm.load_peer_key("gateway-1", KeyPurpose.ENCRYPT)).public_raw
mgr_sign_kp = await server_cm.get_or_create_keypair(KeyPurpose.SIGN)

# 服务端：信封加密 + 加签
sealed = crypto.seal(gw_enc_pub, b"sensitive-config")
signature = Ed25519Signer(mgr_sign_kp.private_raw).sign(sealed.ciphertext)

# 客户端：验签 → 解密
mgr_sign_pub = (await client_cm.load_peer_key("manager-1", KeyPurpose.SIGN)).public_raw
assert Ed25519Verifier(mgr_sign_pub).verify(sealed.ciphertext, signature)
gw_enc_priv = (await client_cm.get_or_create_keypair(KeyPurpose.ENCRYPT)).private_raw
plaintext = crypto.open(gw_enc_priv, sealed)
```
