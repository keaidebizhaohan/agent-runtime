## 进程部署的 runtime-server 启动容器化低码Agent

当 runtime-server 以进程模式部署时，可通过以下两种方式启动容器化低码Agent，两种方式可根据实际部署需求灵活选择。

**方式一：通过 HTTP 请求指定启动模式**

通过发送 HTTP POST 请求，在请求参数中指定 mode=docker，即可触发 runtime-server 启动容器化低码Agent，适用于临时、按需启动容器化Agent的场景。

具体请求命令如下（需根据实际部署环境替换占位参数）：

```
curl -X POST "http://<runtime-server的IP地址>:<runtime-server的port>/api/v1/agents/deploy?name=<低码agent的名字>&mode=docker" -F "file=@<低码agent的ir.json>"
```

**参数说明**：该命令用于触发 runtime-server 按需启动容器化低码Agent，所有尖括号<>包裹的内容为占位参数，需根据实际部署场景替换，具体要求如下：

- <runtime-server的IP地址>：替换为 runtime-server 服务实际部署的主机IP地址（内网/公网均可，需确保请求发起端可访问）；

- <runtime-server的port>：替换为 runtime-server 服务的监听端口（对应 server/.env配置文件中的 PORT 配置项）；

- <低码agent的名字>：替换为自定义的低码Agent名称，建议遵循“业务标识-Agent类型”命名规范，便于区分和管理；

- <低码agent的ir.json>：替换为低码Agent配置文件 ir.json 的本地绝对路径或相对路径，确保发起请求的终端可正常读取该文件，文件格式需符合服务要求。

**方式二：通过配置文件固定启动模式**

在 runtime-server 对应的配置文件 server/.env 中，将 DEPLOY_TYPE 配置项指定为 docker。配置生效后，无论后续收到何种HTTP部署请求，runtime-server 都会强制启动容器化低码Agent，适用于需统一使用容器化Agent的场景。

核心配置如下：

```
DEPLOY_TYPE=docker
```

注意：配置修改后，需重启 runtime-server 进程，确保配置生效。

## 容器部署的 runtime-server 启动容器化低码Agent

当 runtime-server 本身以Docker容器模式部署时，启动容器化低码Agent的操作分为手动启动和一键部署工具启动两种场景，具体操作如下。

**场景一：手动启动 runtime-server 容器**

若手动执行Docker命令启动 runtime-server 容器，需提前确保配置文件 .env 中已设置DEPLOY_TYPE=docker，同时启动容器时需挂载必要的目录，确保容器内服务可正常调用Docker服务。

具体启动命令如下：

```
docker run -d --name <studio-runtime-server的容器名> -v <配置文件.env文件路径>:/app/site-packages/openjiuwen_runtime/server/.env -v /var/run/docker.sock:/var/run/docker.sock <studio-runtime-server的镜像名>
```

**说明：**

- <studio-runtime-server的容器名> 需替换为实际的容器名称，建议遵循“服务名-环境”的命名规范（如 studio-runtime-server-prod）；

- <配置文件.env文件路径> 需替换为本地 .env 配置文件的绝对路径，确保容器内可读取到正确的配置；并且已设置DEPLOY_TYPE=docker。

- 挂载 /var/run/docker.sock 目录，是为了让容器内的 runtime-server 能够调用宿主机的Docker服务，从而启动低码Agent容器；

- <studio-runtime-server的镜像名> 需替换为实际的 runtime-server 容器镜像地址及标签。

**场景二：一键部署工具启动 runtime-server 容器**

若通过官方提供的一键部署工具启动 runtime-server 容器，工具会自动完成 DEPLOY_TYPE=docker 配置及相关目录挂载，无需手动进行任何额外操作，启动完成后 runtime-server 会自动按容器化方式启动低码Agent。

## 注意事项

- 无论哪种部署模式，启动容器化低码Agent前，需确保宿主机Docker服务已正常启动，且 runtime-server 具备访问Docker服务的权限；

- 手动启动容器时，务必确保 .env 配置文件挂载路径正确，否则会导致配置读取失败，同时保证已设置DEPLOY_TYPE=docker，无法启动容器化Agent；

- 若启动失败，可优先检查DEPLOY_TYPE 配置、runtime-server 容器的logs，排查相关异常。

- 对于容器化部署的 runtime-server，仅当低码Agent 以容器化方式启动时，低码Agent 才能正常提供服务，非容器化启动方式将导致Agent服务无法响应请求；
