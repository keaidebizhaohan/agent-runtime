# openJiuwen Agent Runtime 项目介绍

openJiuwen Agent Runtime（简称 Runtime）是 openJiuwen 体系中的智能体运行管理平台，负责将在开发阶段完成的 Agent 发布为可在线调用的运行服务。  
它提供统一的部署、查询、下线与状态管理能力，帮助团队从“开发智能体”平滑过渡到“稳定运行智能体”。

## 项目定位

Runtime 主要解决以下问题：

- 如何把不同类型的 Agent 统一部署并对外服务；
- 如何在多租户场景下隔离不同用户和空间的运行实例；
- 如何支持多种部署方式（进程、Docker、Kubernetes）；
- 如何对运行态 Agent 做生命周期管理（部署、查看、删除、健康检查）。

## 核心能力

### 1）统一的部署管理

Runtime 暴露标准 REST API，可通过配置文件和元数据完成 Agent 部署，支持：

- 部署新 Agent；
- 查询部署列表与详情；
- 删除已部署实例；
- 通过健康检查确认实例状态。

### 2）多部署策略支持

Runtime 内置策略化部署能力，支持三种模式：

- `subprocess`：以独立子进程方式运行 Agent（默认）；
- `docker`：以容器方式运行 Agent；
- `k8s`：在 Kubernetes 集群中运行 Agent。

### 3）多租户隔离

Runtime 在请求处理链路中支持租户信息注入（如 `user_id`、`space_id`），用于隔离不同租户的 Agent 资源和操作范围。

### 4）可扩展架构

Runtime 采用模块化设计，部署策略、Agent 类型、基础能力均可独立扩展，便于在不同业务场景中快速接入新能力。

## 项目架构

Runtime 仓库由多个模块组成：

- `server/`：FastAPI 管理服务，对外提供部署与管理 API；
- `management/`：部署管理核心，负责策略调度与生命周期编排；
- `foundation/`：基础能力组件（配置、数据库、端口、虚拟环境等）；
- `service/`：Agent 服务基类，定义查询、健康检查等通用接口；
- `applications/`：具体 Agent 应用实现（如低码 Agent、工作流 Agent 等）。

## 典型部署流程

1. 客户端调用 Runtime 部署接口，提交 Agent 配置；
2. Runtime 根据配置选择部署策略并创建部署记录；
3. 策略执行器完成实例拉起（进程 / 容器 / K8s）；
4. Agent 服务启动并暴露标准接口（如 `/query`、`/health`）；
5. 业务侧通过 Runtime 或 Agent 地址进行调用与运维管理。

## 适用场景

- 在 openJiuwen Studio 中一键发布智能体到运行环境；
- 企业内部多团队、多租户共享统一 Agent 运行平台；
- 从测试环境到生产环境的 Agent 标准化交付；
- 需要按策略切换部署模式的混合基础设施场景。
